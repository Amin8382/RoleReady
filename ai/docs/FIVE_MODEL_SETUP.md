# RoleReady five-model setup — Windows (Python 3.11 recommended)

**Owner: Mohamed Amin Guesmi.** All five adapters are implemented in the AI package. Model weights have NOT been downloaded by CI and no all-model hardware inference benchmark has been performed.

The [9 November local environment evidence](LOCAL_ENVIRONMENT_2026-11-09.md)
records real CPU/GPU BGE, Whisper and Kokoro smoke results, the exact Windows
dependency snapshot and remaining Qwen/Prometheus gates. Those three small-model
checks do not establish end-to-end integration or model-quality validation.

## Model IDs and official sources

| Model | Hugging Face repository | Purpose |
|---|---|---|
| Qwen | https://huggingface.co/Qwen/Qwen3.5-4B | CV analysis and personalized question generation |
| Prometheus | https://huggingface.co/prometheus-eval/prometheus-7b-v2.0 | Interview answer evaluation using human-reviewed rubric references |
| BGE | https://huggingface.co/BAAI/bge-small-en-v1.5 | Embedding model used with FAISS |
| Whisper | https://huggingface.co/Systran/faster-whisper-small.en | English speech recognition using a CTranslate2 conversion |
| Kokoro | https://huggingface.co/hexgrad/Kokoro-82M | English question narration |

FAISS is a vector index, not a sixth model. Run large Qwen and Prometheus inference services on appropriate GPU hardware or separate hosted infrastructure, subject to CV privacy requirements. Neither service is launched by these Python adapters.

## First real model checks — install only if you want to download weights

BGE / FAISS:

    python -m pip install -e ".[retrieval,test]"
    python -m roleready_ai.model_smoke bge

Whisper / Kokoro (may require espeak-ng on Windows for English phonemization):

    python -m pip install -r requirements-voice.txt
    python -m roleready_ai.model_smoke kokoro --output outputs/question.wav
    python -m roleready_ai.model_smoke whisper --audio outputs/question.wav

The second command tests Whisper on the synthetic question audio generated by Kokoro. These commands may download official model weights. Outputs are private, gitignored files. Consult the upstream Kokoro installation instructions if eSpeak-ng is missing; do not use untrusted executable installers.

For revision-resolved synthetic checks with separate artifact preparation, model
loading and inference timings, use the optional local benchmark. BGE uses three
questions to verify semantic ranking and role filtering. GPU embeddings use
PyTorch, while the FAISS index remains on CPU. Kokoro checks for finite, non-silent
24 kHz audio. Whisper returns a transcript for manual comparison with the source.

    $env:HF_HOME="$PWD/.runtime/huggingface"
    $env:HF_HUB_DISABLE_TELEMETRY="1"
    $env:HF_HUB_DISABLE_IMPLICIT_TOKEN="1"
    $env:HF_HUB_DISABLE_XET="1"
    .\.venv311\Scripts\python.exe -m roleready_ai.local_benchmark bge --device cuda --report outputs/bge-cuda.json
    .\.venv311\Scripts\python.exe -m roleready_ai.local_benchmark kokoro --device cuda --report outputs/kokoro-cuda.json
    .\.venv311\Scripts\python.exe -m roleready_ai.local_benchmark whisper --device cpu --report outputs/whisper-cpu.json

For CUDA Whisper on this verified Windows environment, expose the venv's bundled
cuBLAS/cuDNN libraries to the current shell only, then use `--device cuda`:

    $env:PATH="$PWD/.venv311/Lib/site-packages/torch/lib;$env:PATH"
    .\.venv311\Scripts\python.exe -m roleready_ai.local_benchmark whisper --device cuda --report outputs/whisper-cuda.json

The benchmark downloads only the selected model's required files, records the
resolved publisher commit and writes failure details as well as successes. Use
`--revision COMMIT_SHA` to repeat a recorded revision. Timings exclude Python
import overhead; artifact preparation includes any missing downloads and is not
pure model loading. GPU snapshots include other desktop processes. PyTorch peak
allocation excludes CTranslate2 memory, so it is not Whisper's peak VRAM use.
Install the pinned spaCy `en_core_web_sm` language dependency before measuring
Kokoro model loading; otherwise its first KPipeline construction may include
that auxiliary download/install in the model-load phase.

## Qwen and Prometheus endpoint setup

First start actual compatible model servers (local GPU or remote); the following commands merely configure clients. Verify that the served model names match your servers.

    $env:ROLEREADY_QWEN_BASE_URL="http://127.0.0.1:8001/v1"
    $env:ROLEREADY_QWEN_MODEL="Qwen/Qwen3.5-4B"
    $env:ROLEREADY_PROMETHEUS_BASE_URL="http://127.0.0.1:8002/v1"
    $env:ROLEREADY_PROMETHEUS_MODEL="prometheus-eval/prometheus-7b-v2.0"
    python -m roleready_ai.model_smoke qwen
    python -m roleready_ai.model_smoke prometheus

Set server-side ROLEREADY_QWEN_API_KEY and ROLEREADY_PROMETHEUS_API_KEY if required. Remote services must use HTTPS. The Qwen model card documents vLLM/SGLang OpenAI-compatible serving; check compatibility with your exact hardware before starting.

The Prometheus adapter uses four rubric dimensions and expects a terminal [RESULT] integer 1–5. It refuses scoring without a reviewed reference answer. These scores are experimental and must be calibrated to human ratings.

## Meaning of ready

- Source code and tests pass: **code ready**
- Each model loads, downloads required weights if absent, and completes real inference: **runtime ready**
- Frontend -> FastAPI -> AI/voice/scoring works: **integrated**
- Held-out quality and human evaluation pass: **validated**

The current PR delivers code-ready integrations, not proof of all four gates.
